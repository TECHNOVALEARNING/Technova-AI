# Rules
- Landing page texts live in src/lib/i18n.ts (FR/EN/ES/PT as `SiteLang`; dashboard and auth stay FR/EN as `Lang`, falling back to English via appLang) — keeps the public languages in sync in one place.
- Scroll reveal uses the `.reveal` CSS class + IntersectionObserver in index.tsx — no animation library needed.
- The hero/about videos, posters and dashboard wallpaper are static files in public/media referenced through src/lib/media.ts, with a poster fallback — keeps the opening screen usable without autoplay.
- The About statement uses an in-flow, scroll-driven per-word color transition in both languages, with a reduced-motion fallback — keeps reading progress visible.
- « Comment ça marche » (How in index.tsx) is a horizontal accordion of four black-and-white portraits (src/assets/how-step-1..4.webp, generated for TechNova): hovering, focusing or tapping a step opens it — photo on the left, kicker, title, text and chips (i18n how.steps k / t / d / c) on the site's black gradient; phones stack the steps and open one at a time (.how-* in styles.css, static with reduced motion).
- The About video is a narrated presentation (technova-about-v3: 1080p MP4 + WebM, French voice-over, captions technova-about-v3.vtt as a <track>, poster technova-about-poster-v3.jpg), opened on demand in an accessible overlay that plays with sound after the click — avoids preloading large media.
- Prominent landing-page actions use the shared Button pill variant, semantic `.action-pill-*` surfaces, and `ActionText` for a stationary color-wash/rolling-label interaction — keeps destinations intact while honoring reduced-motion preferences.
- Connection, registration, and password recovery share one bilingual auth component backed by Supabase Auth (Google via supabase.auth.signInWithOAuth); profiles hold display information under owner-only policies — keeps identity separate from profile data and the screens consistent.
- The landing navigation keeps primary action visible on small screens and moves section links, sign-in, and language into a dismissible menu below the desktop breakpoint — keeps every destination accessible without crowding the header.
- Dashboard sidebar (sideGroups in DashboardLayout): a black « Nouvelle conversation » button, « Vue d'ensemble », then three labelled groups — Créer (Chat IA, Projets, Créativité and Tableur as direct links to /dashboard/registry?section=design|sheet, Apprendre, Templates), Automatiser (Agents IA, Plugins, Connaissances), Compte (Tarifs et crédits, Entreprise for company members, Administration for admins) — then the history; no « Plus » toggle; group labels become thin dividers in the icon-only menu; items a company unticked are hidden. Account pages (Paramètres, Connexions, Utilisation, Facturation, Modes et prix, API, Parrainage, Thèmes, aide) are only in the profile menu. Dashboard uses separate content routes, local appearance preferences, viewport-fixed CDN wallpaper in both themes, and owner-scoped conversations — keeps backgrounds stable and history private.
- The chat composer offers a mode selector (Éclair by default, Smart wand icon on the trigger) (Éclair, Équilibré, Expert with Font Awesome icons, then TechNova Smart, which picks the mode per message via smartTier; src/lib/chat-modes.ts — Smart reads whole words only (textSignals, accents folded): Éclair by default, Équilibré for code, analysis, files or long messages, Expert only for a really heavy technical job, never for everyday words like "paiement" or "mobile money"; Smart agents use the same signals: Gemini 2.5 Flash Lite, then Qwen3 235B, DeepSeek V3 for code, Claude Sonnet 5 only for heavy jobs) instead of model names: /api/chat picks the engine server-side (Starter/Essential get Éclair and Équilibré; Expert opens from Creator at 25/26 credits and uses a stronger engine on Pro at 60/65), charges the mode's fixed credits or, when higher, the real cost OpenRouter reports at the end of the stream (usage.cost × 1 200, hidden reasoning included), and records mode, engine, tokens and cost in chat_engine_costs (service_role only, migration 0039) for the admin console's cost-per-mode table; media are five choices (mediaTiers in media-models.ts, HD/quality chosen from the request wording, failures refunded): images and music at a fixed price; videos last 4-15 s (both kie.ai engines take any whole second, billed per second by kie.ai) and cost the listed 5-second price × seconds / 5 (videoCredits), the length read from the request (videoSecondsFrom: « 8 secondes », « 10 s », "8-second") or chosen in VideoWizard (5, 8, 10, 15 s), 5 s by default; custom agents and the public API keep named models — engines never appear in the dashboard; the choice stays browser-local and messages owner-scoped.
- Visuals use server-only kie.ai tasks in owner-scoped messages — keeps keys private.
- The chat welcome derives its bilingual time-of-day phrase from the visitor's local browser time and uses the signed-in profile name when available — personalizes the greeting without weather permissions or SSR time-zone assumptions.
- Public conversation sharing uses an unguessable per-thread share token read through a security-definer lookup function — lets signed-out visitors read one shared conversation without opening table access.
- Public landing pages (Models, Blog, Documentation — which also holds the developer guide; /developpeurs redirects to /documentation#exemples) share header/footer/hero from src/components/site/SiteChrome with a browser-local language choice; their copy lives in src/lib/site-pages.ts — consistent branding.
- Credit balance is the sum of a server-written credit ledger (welcome bonus via security-definer function, chat usage debited in /api/chat); API keys are stored hashed and shown once — users can never mint their own credits.
- Créer mode runs the TechNova Studio pipeline (/api/studio: intent → questions → plan → build) on OpenRouter (STUDIO_MODEL), persisting each stage as a data-studio part in chat_messages; the chat shows one compact activity entry whose detail timeline expands in the artifact panel alongside generated files — keeps plan approval before code without cluttering the conversation and restores artifacts on reload.
- Studio builds run as server-side jobs (studio_jobs + /api/studio-job), saving progress into the chat message; a per-minute pg_cron worker (/api/public/studio-worker, URL from studio_worker_config.app_url set by configure_app_url) armed on job insert and disarmed when idle resumes interrupted builds — generation survives page reloads and closed tabs.
- Users link their own Supabase through an OAuth popup (startSupabaseConnect / completeSupabaseConnect + /api/public/supabase-oauth/callback); tokens live encrypted per owner in supabase_connections and are read only by server functions — keeps each user's database separate and never readable from the browser.
- Studio SQL is generated for review/copy only; the connected Supabase project is selected in Settings, and no automatic database execution exists yet — avoids implying plan approval writes to an external database.
- Studio previews (artifact panel, /apercu/$token, published /s/$slug) all render through previewDoc (src/lib/studio.ts) in a sandboxed srcdoc iframe without same-origin (allow-popups-to-escape-sandbox so external links open normally): PREVIEW_BRIDGE runs first in <head> — in-memory localStorage/sessionStorage/cookie, "#section" links scrolled inside the page (in srcdoc they would resolve against TechNova's URL), internal pages relayed to the viewer, external sites in a new tab, forms answered with a notice, JS errors reported; if a page still escapes (JS location change), __root's first inline script sees TechNova running in an opaque-origin frame, hides itself and posts technova-preview-escape so the viewer reloads the right page — TechNova never runs inside a preview. Write the bridge without backslashes (it lives in a template literal). checkBuild lists missing pages, assets, anchors and cut files (jsSyntaxIssues adds unparsable classic JavaScript); after every build the job runs autoRepair once (studio-job.server.ts): it appends a visible « Vérification automatique » step and, when something is wrong, one STUDIO_MODEL call (16 000 tokens max, included in the build price) rewrites only the faulty or missing files, appended as later <file> tags that replace the earlier ones in parseBuild; the panel's Vérification bar adds runtime errors and "Demander la correction" pre-fills the composer. Code, SQL and Activity show Xcode-dark syntax colours (src/components/CodeHighlight.tsx: HTML with its style/script blocks, CSS, JS/TS/JSON, SQL).
- Studio context and changes: the questions and plan prompts first pin down the kind of site, the business, what it sells and to whom, and never drift to another activity suggested by one word. In a conversation that already has a finished build, a Créer message is classified with the project (intent "build" | "edit" | "chat", edit preferred): a change skips the questions and goes straight to a modification plan made with the project summary (currentProject in ChatWorkspace: original request, answers, plan, latest change, file list) and saved with plan.edit + plan.base (the build message changed); the build job then starts from that build's files (baseProjectFiles, EDIT_RULES) and the model outputs only changed or new files. Responsive design is part of the build prompt (mobile-first, viewport tag, no fixed px widths, one-column grids on phones, a menu button below 1024px, a closed mobile menu hidden rather than parked off-screen, nothing scrolling sideways at 390px) and of the checks: checkBuild adds no_viewport / not_responsive / fixed_width (fixed by autoRepair), and the preview bridge measures horizontal overflow at the current width (technova-preview-layout, shown per phone/tablet/desktop in the Vérification bar). parseBuild ends a tag at its closing tag or at the next <step>/<file>/<sql> (models sometimes close a file with </step>).
- Studio design default (questions, plan and build prompts): unless the user asks for another style, sites are modern, professional and clean — light neutral base, one restrained accent colour, generous white space, aligned grid, clear type hierarchy, subtle borders and shadows; never neon, glow, saturated or rainbow gradients, cyberpunk backgrounds or decorative blobs. A requested style (minimalist, colourful, dynamic, luxurious, dark…) is followed but kept professional. The build prompt's DESIGN STANDARD aims at the polish of the best brand sites (Apple, Stripe, Linear, Airbnb): 1120-1200px content width, 8px spacing scale, generous section padding, a Google Fonts sans (Inter, Manrope, Plus Jakarta Sans, DM Sans; Fraunces or Playfair Display headings only for fashion, food, luxury, editorial), clamp() type scale, one accent colour, sticky translucent header, consistent radius, CSS variables for tokens, no emoji; the menu button only below 1024px, never next to the full navigation, and the logo never wraps. Icons are Font Awesome Free 7.3.1 only (cdnjs all.min.css with its SRI hash in every page head; fa-solid / fa-regular / fa-brands, never emoji, icon images or hand-drawn SVG icons) — free, attribution is the licence header inside the file, nothing to show or bill; checkBuild flags fa- classes without the stylesheet (missing_icons, fixed by autoRepair).
- Studio billing: a build costs max(STUDIO_COST.build = 250, real provider cost × 1 200), capped at STUDIO_BUILD_MAX = 800 (src/lib/studio.ts, studioBuildCredits); /api/studio-job reserves 800, else 525, else 250, and the job never bills more than its reservation (the rest returns to the balance). studioStream (studio-gateway.server.ts) asks OpenRouter for usage.include and reads the real USD cost from a copy of the response (costUsd()); the job adds every attempt (studio_jobs.cost_usd, migration 0045, skipped until run) and the automatic repair, appends a visible « Facturation » step, logs usage_logs and a chat_engine_costs row (mode studio_build; studio_questions / studio_plan / studio_intent for the other stages, labelled in the admin cost table). The plan dialog, the sales-page wizard and the docs say "250 credits for a standard site, real cost beyond, 800 at most" — questions (3) and plan (80) stay fixed.
- Studio clarification shows one persisted question set as a step-by-step client flow, and the plan is reviewed in a dialog before approval — preserves the existing approval boundary without changing the generation API.
- The artifact workspace temporarily collapses dashboard navigation and gives the resizable artifact panel a majority split when generation begins; manual resizing and menu toggles remain available — maximizes working space without changing saved navigation preferences. The chat column is capped at 560 px only until the user drags the separator; after that it takes all the space the panel leaves (chat at least 380 px, panel at least 360 px). The Code tab's grid row is bounded (grid-rows-[minmax(0,1fr)]) so the file list and the code scroll inside the panel under a sticky file header. A shared preview link (/apercu/$token) shows the site alone, full screen (no TechNova bar, title or device buttons), like a published site.

- The public Models page lists only models usable in TechNova (src/lib/public-models.ts, built from chat-models, model-pricing and media-models; src/lib/openrouter-catalog.ts is a generated list of the other OpenRouter chat models that answered a data_collection "deny" test request, priced at USD × 1 200, usable through the public API and custom agents, Arena stays on coreModelIds; the site copy says "200+ models"; the page is a market layout: an auto-playing cross-fade banner carousel (TechNova Smart first) and cover cards with pictures from public/media/models — a model's own cover (ownCovers in modeles.tsx, each picture used once) and a fixed picture per media creation, every other model a drawn cover (src/components/site/ModelArt.tsx: seeded by the model name, provider hue shifted per model, motif from its strengths or a generic one) so no two cards repeat; pictures never show the upstream provider's logo (cropped or left out) — provider and task chip filters, 24 cards then "show more") with prices in Technova credits, and never names or links the upstream provider — what is shown is what is sold, except the showcaseOnly entries in public-models.ts (GPT-6 Astra, Gemini 4 Argon), listed by request but kept out of openRouterModelIds so nobody can run them at a loss.
- Pricing/footer: src/components/site/AGENTS.md — scoped guidance.
- Per-user accounts (GitHub, Google Drive, Notion) use direct OAuth with TechNova's own apps and HMAC-signed state; tokens are AES-GCM encrypted in app_user_connections; sites publish to /s/$slug; rate limits/security log in security.server.ts — secrets stay server-side.
- Custom agents (owner-scoped, versioned by trigger) feed /api/chat via agentId; server enforces per-reply budget and tools stay deny-by-default — browser never decides cost.
- Deployment targets Vercel through Nitro's vercel preset (vite.config.ts); security headers are added in src/server.ts and user-supplied URLs are fetched only through safe-fetch.server.ts — no platform-specific SDKs.
- Credit/system SQL functions are executable by service_role only (migration 0017); the public API /api/ai/chat authenticates hashed tn_live_ keys — browsers can never mint credits.
- New accounts answer a 3-question onboarding (/bienvenue: account type, field, referral source) stored on their own profile; the dashboard route redirects until profiles.onboarded_at is set, and admins see only aggregated answers — keeps sign-up short and acquisition data private.
- The app is an installable PWA: public/manifest.webmanifest, public/sw.js (network-first pages with offline.html fallback, cache-first static assets, never API/auth/payments) registered in production from src/lib/pwa.ts, plus a dismissible install card on the landing page (InstallAppPrompt, shown after the hero, snoozed 14 days) — bump VERSION in sw.js when precached files change.
- Pack prices are billed in FCFA; /api/public/geo-price maps the visitor country (x-vercel-ip-country) to a currency, exact for EUR/CFA pegs and "≈" daily ExchangeRate-API rates otherwise, falling back to FCFA; it also returns USD/EUR rates, and both the public pricing grid and the dashboard (Credits, Billing, Settings) read it through src/lib/geo-price-client.ts — shows local prices everywhere without changing what is charged.
- Footer trust badges link to the official EU data-protection and EDPB rights pages; App Store/Google Play badges are non-interactive "coming soon" marks until the native apps exist (src/components/site/Badges.tsx).
- Chat files and knowledge bases share one server pipeline (src/lib/files.server.ts: validate → scan → extract → chunk → embed → index) fed by signed uploads to the private user-files bucket; small images/PDF/audio/video still go straight to the model, other formats travel as `tnfile:` references; browsers only read their own rows, embeddings stay server-only and match_document_chunks is service_role-only (migration 0031) — keeps documents private and indexing billed at real cost.
- RAG context is injected by /api/chat from fileIds (inlined when small, retrieved otherwise) and knowledge bases chosen in the composer or attached to an agent, framed as untrusted data; the allowed formats and size limits live in src/lib/file-types.ts — one list for browser and server.
- The Registry is shown to users as « Templates » (sidebar, page, docs, legal texts; code, routes /dashboard/registry and tables keep the registry name). Official Registry items are original TechNova designs kept as files in drizzle/registry/ (manifest.json) and installed by a generated, re-runnable migration (node scripts/build-registry-migration.mjs <new migration name>, latest 0037); HTML items preview in sandboxed iframes without same-origin — one reviewable source for content and safe live previews.
- Official Registry designs are included with Creator and Pro: RLS, registry_download and registry_remix go through registry_item_open (migration 0036), Starter/Essential keep one open design (Halo, …0101) and see the rest as locked cards from registry_catalog (metadata only) — content never reaches accounts without access.
- Arena is hidden for now (no links; /classement and /dashboard/arena redirect, code kept). The public Arena ranking (/classement) is loaded by a server function that returns only the aggregated arena_leaderboard rows (blind votes), never battles or voters — public trust content without exposing user data.
- The admin console (/dashboard/admin, sidebar link for admins only) reads revenue, users and credit totals through service_role-only SQL aggregates (migration 0033) called from server functions that re-check has_role; suspensions combine an auth ban with account_suspensions, which /api/chat and API-key auth also check; the credit transfer history shows each recipient's name and e-mail (listCreditTransfers reads them server-side) — admin power stays server-side and the ledger is never loaded whole.
- Pro pack: 9 000 FCFA → 10 000 credits (migration 0058, fallbackPacks; ≥ 35 % margin at full cost). Plan limits from the /tarifs table (except the development/terminal section) live in src/lib/plans.ts; the tier is the highest credited pack (account_tier, migration 0034, service_role only) and every gated action re-checks it on the server (plan.server.ts) or in a trigger (share links, agents), answering PLAN_UPGRADE_REQUIRED:<feature> that the UI turns into an upgrade message — the browser never decides access.
- "Credits used" (dashboard overview, admin users) is read from the credit ledger like the balance (charge + usage + reserve + refund, migration 0035); media generations also write usage_logs so the Usage page lists them — used and remaining always add up.
- Cookie consent (src/lib/consent.ts + CookieConsent in __root, hidden on /s/ user sites): accept / reject / customize with equal weight, choice kept 6 months; strictly necessary storage and explicitly chosen language/theme (EXPLICIT_CHOICE_KEYS) need no consent, other preference keys go through savePref and are wiped on refusal; no analytics or ads exist — the /cookies policy (FR, authoritative) lists every key and must be updated when storage changes.
- Songs described without own lyrics or an instrumental request get lyrics written first (writeSongLyrics in media-generation.functions.ts: Gemini 2.5 Flash, JSON title/style/lyrics in the description's language, included in the music price, chat_engine_costs mode "music_lyrics") and go to kie.ai custom mode, so they are really sung. Songs show as an album card (MusicAlbum.tsx, 4:3, max 560 px): cover from the music engine (archived with the MP3 as a second file; a drawn cover when missing) blurred behind, title, style, duration, big play button, progress bar, « Télécharger (MP3) » and, only when the AI wrote the lyrics, « Paroles (.txt) » plus « Voir les paroles »; media_generations.result_meta (migration 0054) keeps title, lyrics, tags, duration, ownLyrics and instrumental. Other generated media show bare in the chat (no frame, no prompt) with Download and, for images, Edit: Edit puts the image in the composer and the next message runs imageEditModel (google/nano-banana-edit, not in the pickers) with the archived file as source (sourceId, owner-checked, 14-day retention); link previews on every page use the hero poster (absolute og:image).
- Dashboard themes (src/lib/dashboard-themes.ts, menu under "Thèmes" in the profile menu, stored in technova-dashboard-theme): Brume, Soie, Crépuscule, Abysse, Améthyste (dark) and Pastel, Azur, Givre, Perle (light, Azur by default; Perle is the pearl-grey gradient of the FAQ reference image); Azur/Crépuscule follow the ivory-haze mockup, Abysse/Améthyste the two dark reference images (look-specific orb, composer edge and sidebar); retired Apple/Papier/Sable/Ciel/Ivoire open Azur, Réverbère/Graphite/Obsidienne open Brume; on desktop the sidebar floats as a rounded glass card inside a padded shell, and menus/dialogs over the dashboard are frosted but near-opaque; Soie also restyles the sidebar glass; the mode drives the sidebar, the look only restyles .dashboard-content (wallpaper gradients, glows, glass variables, composer edge) — only Soie changes the sidebar (its glass and a moving light), by explicit request.
- Dashboard content panels (bordered bg-card surfaces in main; the old « Sites à visiter » bottom marquee was removed by request; today's date shows at the top left of the content; the chat home has no "recent conversations" block, history lives in the sidebar) turn into the ivory-haze mockup's flat frosted glass from CSS alone in styles.css (55% fill in the look's tint, blur 40px saturate 150%, soft ambient shadow, no border/rim/sheen; nested cards and tints use a 70% "chip" glass; the desktop sidebar uses the same panel glass), except chat threads, the composer and portaled dialogs; dashboard sidebar is frosted glass (sidebar-glass) with a faint West-African-textile pattern on every look (barely visible in dark mode), and below the lg breakpoint it is a fuller, strongly blurred glass so nothing behind it stays readable; dashboard grid cells get min-width 0 so long titles truncate instead of widening panels past a phone screen; the plan badge and the spinning avatar ring take the colours of the highest pack bought (plan-<key> classes, usePlan); a confirmed payment opens PaymentSuccess (confetti, drawn tick, credits added) before reloading.
- Confirmations use confirmDialog / promptDialog (src/components/ConfirmHost.tsx, host mounted in __root): one accessible modal with title, explanation and Cancel / action buttons (red for destructive actions, tone "danger"; promptDialog's input takes a defaultValue) — never window.confirm, alert or prompt.
- Payments are orchestrated server-side (payment-routing.ts + payments.functions.ts): cards and Mobile Money of FeexPay-covered countries/operators go to FeexPay (feexpay.server.ts, webhook /api/public/feexpay-webhook with a Bearer secret), everything else and any FeexPay failure to Nyole; the card tab asks only a phone number (the visitor's country code added to a local number) and one "Payer par carte" button opens the FeexPay page in a new tab; country and city come from x-vercel-ip-country/x-vercel-ip-city; cards never fall back to Nyole (no card page there): a FeexPay refusal marks the payment failed, logs payment_card_failed and shows FeexPay's reason (CARD_FAILED:/CARD_UNAVAILABLE:); payments.server.ts re-reads the provider status and credits once — config in docs/paiements-feexpay.md, secrets only in Vercel.
- Account deletion (Settings → Supprimer mon compte, account_deletions, migration 0038) keeps everything 30 days, cancellable from a dashboard banner after signing in again; the daily /api/public/media-purge then removes stored files and the auth user (cascade), while payment records (no foreign key) stay for accounting — the privacy policy states this delay.
- SEO: public routes build their head with pageHead (src/lib/seo.ts: canonical on www.technovaihub.com, og/twitter tags, robots, JSON-LD Organization/WebSite/WebApplication/FAQPage/Breadcrumb from real content); private routes are noindex; public/robots.txt, public/sitemap.xml (update when a public page is added) and public/llms.txt describe the site to crawlers — one place for search metadata.
- Chat thread: a disclaimer sits above the chat box, prompts you sent offer resend / copy / share / edit (edit puts the text back in the box), generated images open full screen (portal viewer, Esc to close), the thinking state and media in progress show the turning ThinkingSpinner (it also pulses, growing and shrinking back; rotation only with reduced motion) with « Réflexion en cours » above an even blue dot field in one 4:3 frame up to 640 px wide for every creation, with real progress (or elapsed time), the dashboard content shows a thin visible scrollbar (sidebar stays clean), and media requests are detected from infinitives and polite forms (« peux-tu générer une image… ») while the chat prompt says TechNova creates media itself.
- Abuse guards: every billable action reserves credits first through reserveCredits (credits.server.ts), which also refuses suspended accounts (assertNotSuspended, media too); a chat reply stopped by the visitor is still billed at least the mode price; the public API reserves the worst case before calling the provider and bills usage.cost; the welcome bonus needs a confirmed e-mail (migration 0040).
- Every OpenRouter request (chat, public API, Studio, file extraction, embeddings) sends provider.data_collection "deny", so only providers that neither store prompts nor train on them answer — this backs the privacy cards (RGPD, no training, no provider retention) in the landing "Pourquoi nous choisir" section; check a new model still answers with it before adding it.
- Generated media links saved in conversations are storage URLs signed until the file's expires_at (14-day retention), re-signed and re-saved when an old creation is opened; a small orange banner in the chat reminds the 14-day limit for 15 s after a creation finishes (not permanently).
- Old tabs after a deployment (src/lib/stale-build.ts, installed in __root): a build id (vite define __BUILD_ID__, /api/public/version) is checked when a tab wakes up, on a failed chunk preload and on a 404 server function; a stale tab shows a "new version" toast and loads internal links from the server, and the root error component reloads at most once every 20 s for a missing chunk (timestamp, not a sticky flag) — a deployment never leaves visitors on "page didn't load".

Dashboard sidebar wording: "Thèmes", "Modes" (models page), "Tarifs et crédits" (credits page).

- « Apprendre » (/dashboard/apprendre, LearnPage in src/components/learn/, sidebar Créer group, chip under the chat): an Élève / Enseignant switch (technova-learn-audience, a preference through savePref) over tool cards defined in src/lib/learn.ts — students: Tuteur guidé, Mes cours (document required: PDF / photo / Word through the chat file pipeline, or pasted text), Quiz et QCM, Flashcards, Plan de révision, Expliquer autrement, Préparer un examen (original practice paper, never presented as official past papers); teachers: Plan de cours, Quiz / exercices / examens (printable, barème + corrigé), Grille d'évaluation, Aide à la correction, Adapter un texte.
