# Rules
- Landing page texts live in src/lib/i18n.ts (FR/EN/ES/PT as `SiteLang`; dashboard and auth stay FR/EN as `Lang`, falling back to English via appLang) — keeps the public languages in sync in one place.
- Scroll reveal uses the `.reveal` CSS class + IntersectionObserver in index.tsx — no animation library needed.
- The hero/about videos, posters and dashboard wallpaper are static files in public/media referenced through src/lib/media.ts, with a poster fallback — keeps the opening screen usable without autoplay.
- The About statement uses an in-flow, scroll-driven per-word color transition in both languages, with a reduced-motion fallback — keeps reading progress visible.
- The Process line and step surfaces derive their fill from one scroll-progress value in index.tsx — keeps illumination synchronized with reading position.
- The About video uses a 4K-upscaled MP4 plus compatible WebM and a separate poster, opened on demand in an accessible overlay — avoids preloading large media.
- Prominent landing-page actions use the shared Button pill variant, semantic `.action-pill-*` surfaces, and `ActionText` for a stationary color-wash/rolling-label interaction — keeps destinations intact while honoring reduced-motion preferences.
- Connection, registration, and password recovery share one bilingual auth component backed by Supabase Auth (Google via supabase.auth.signInWithOAuth); profiles hold display information under owner-only policies — keeps identity separate from profile data and the screens consistent.
- The landing navigation keeps primary action visible on small screens and moves section links, sign-in, and language into a dismissible menu below the desktop breakpoint — keeps every destination accessible without crowding the header.
- Dashboard sidebar shows Overview, AI Chat, Agents and Credits, with the other sections under a "Plus" toggle (unfolded while one is open) so the history has room. Dashboard uses separate content routes, local appearance preferences, viewport-fixed CDN wallpaper in both themes, and owner-scoped conversations — keeps backgrounds stable and history private.
- The chat composer offers a mode selector (Éclair by default, Smart wand icon on the trigger) (Éclair, Équilibré, Expert with Font Awesome icons, then TechNova Smart, which picks the mode per message via smartTier; src/lib/chat-modes.ts — Smart reads whole words only (textSignals, accents folded): Éclair by default, Équilibré for code, analysis, files or long messages, Expert only for a really heavy technical job, never for everyday words like "paiement" or "mobile money"; Smart agents use the same signals: Gemini 2.5 Flash Lite, then Qwen3 235B, DeepSeek V3 for code, Claude Sonnet 5 only for heavy jobs) instead of model names: /api/chat picks the engine server-side (Starter/Essential get Éclair and Équilibré; Expert opens from Creator at 25/26 credits and uses a stronger engine on Pro at 60/65), charges the mode's fixed credits or, when higher, the real cost OpenRouter reports at the end of the stream (usage.cost × 1 200, hidden reasoning included), and records mode, engine, tokens and cost in chat_engine_costs (service_role only, migration 0039) for the admin console's cost-per-mode table; media are five fixed-price choices (mediaTiers in media-models.ts, HD/quality chosen from the request wording, failures refunded); custom agents and the public API keep named models — engines never appear in the dashboard; the choice stays browser-local and messages owner-scoped.
- Visuals use server-only kie.ai tasks in owner-scoped messages — keeps keys private.
- The chat welcome derives its bilingual time-of-day phrase from the visitor's local browser time and uses the signed-in profile name when available — personalizes the greeting without weather permissions or SSR time-zone assumptions.
- Public conversation sharing uses an unguessable per-thread share token read through a security-definer lookup function — lets signed-out visitors read one shared conversation without opening table access.
- Public landing pages (Models, Blog, Documentation — which also holds the developer guide; /developpeurs redirects to /documentation#exemples) share header/footer/hero from src/components/site/SiteChrome with a browser-local language choice; their copy lives in src/lib/site-pages.ts — consistent branding.
- Credit balance is the sum of a server-written credit ledger (welcome bonus via security-definer function, chat usage debited in /api/chat); API keys are stored hashed and shown once — users can never mint their own credits.
- Créer mode runs the TechNova Studio pipeline (/api/studio: intent → questions → plan → build) on OpenRouter (STUDIO_MODEL), persisting each stage as a data-studio part in chat_messages; the chat shows one compact activity entry whose detail timeline expands in the artifact panel alongside generated files — keeps plan approval before code without cluttering the conversation and restores artifacts on reload.
- Studio builds run as server-side jobs (studio_jobs + /api/studio-job), saving progress into the chat message; a per-minute pg_cron worker (/api/public/studio-worker, URL from studio_worker_config.app_url set by configure_app_url) armed on job insert and disarmed when idle resumes interrupted builds — generation survives page reloads and closed tabs.
- Users link their own Supabase through an OAuth popup (startSupabaseConnect / completeSupabaseConnect + /api/public/supabase-oauth/callback); tokens live encrypted per owner in supabase_connections and are read only by server functions — keeps each user's database separate and never readable from the browser.
- Studio SQL is generated for review/copy only; the connected Supabase project is selected in Settings, and no automatic database execution exists yet — avoids implying plan approval writes to an external database.
- Studio clarification shows one persisted question set as a step-by-step client flow, and the plan is reviewed in a dialog before approval — preserves the existing approval boundary without changing the generation API.
- The artifact workspace temporarily collapses dashboard navigation and gives the resizable artifact panel a majority split when generation begins; manual resizing and menu toggles remain available — maximizes working space without changing saved navigation preferences.

- The public Models page lists only models usable in TechNova (src/lib/public-models.ts, built from chat-models, model-pricing and media-models; src/lib/openrouter-catalog.ts is a generated list of the other OpenRouter chat models that answered a data_collection "deny" test request, priced at USD × 1 200, usable through the public API and custom agents, Arena stays on coreModelIds; the site copy says "200+ models"; the page is a market layout: an auto-playing cross-fade banner carousel (TechNova Smart first) and cover cards with pictures from public/media/models — a model's own cover (ownCovers in modeles.tsx, each picture used once) and a fixed picture per media creation, every other model a drawn cover (src/components/site/ModelArt.tsx: seeded by the model name, provider hue shifted per model, motif from its strengths or a generic one) so no two cards repeat; pictures never show the upstream provider's logo (cropped or left out) — provider and task chip filters, 24 cards then "show more") with prices in Technova credits, and never names or links the upstream provider — what is shown is what is sold, except the showcaseOnly entries in public-models.ts (GPT-6 Astra, Gemini 4 Argon), listed by request but kept out of openRouterModelIds so nobody can run them at a loss.
- Pricing/footer: src/components/site/AGENTS.md — scoped guidance.
- Per-user accounts (GitHub, Google Drive, Notion) use direct OAuth with TechNova's own apps and HMAC-signed state; tokens are AES-GCM encrypted in app_user_connections; sites publish to /s/$slug; rate limits/security log in security.server.ts — secrets stay server-side.
- Custom agents (owner-scoped, versioned by trigger) feed /api/chat via agentId; server enforces per-reply budget and tools stay deny-by-default — browser never decides cost.
- Deployment targets Vercel through Nitro's vercel preset (vite.config.ts); security headers are added in src/server.ts and user-supplied URLs are fetched only through safe-fetch.server.ts — no platform-specific SDKs.
- Credit/system SQL functions are executable by service_role only (migration 0017); the public API /api/ai/chat authenticates hashed tn_live_ keys — browsers can never mint credits.
- New accounts answer a 3-question onboarding (/bienvenue: account type, field, referral source) stored on their own profile; the dashboard route redirects until profiles.onboarded_at is set, and admins see only aggregated answers — keeps sign-up short and acquisition data private.
- The app is an installable PWA: public/manifest.webmanifest, public/sw.js (network-first pages with offline.html fallback, cache-first static assets, never API/auth/payments) registered in production from src/lib/pwa.ts, plus a dismissible install card on the landing page (InstallAppPrompt, shown after the hero, snoozed 14 days) — bump VERSION in sw.js when precached files change.
- Pack prices are billed in FCFA; /api/public/geo-price maps the visitor country (x-vercel-ip-country) to a currency, exact for EUR/CFA pegs and "≈" daily ExchangeRate-API rates otherwise, falling back to FCFA; it also returns USD/EUR rates, and both the public pricing grid and the dashboard (Credits, Billing, Settings) read it through src/lib/geo-price-client.ts — shows local prices everywhere without changing what is charged.
- Footer trust badges link to the official EU data-protection and EDPB rights pages; App Store/Google Play badges are non-interactive "coming soon" marks until the native apps exist (src/components/site/Badges.tsx).
- Chat files and knowledge bases share one server pipeline (src/lib/files.server.ts: validate → scan → extract → chunk → embed → index) fed by signed uploads to the private user-files bucket; small images/PDF/audio/video still go straight to the model, other formats travel as `tnfile:` references; browsers only read their own rows, embeddings stay server-only and match_document_chunks is service_role-only (migration 0031) — keeps documents private and indexing billed at real cost.
- RAG context is injected by /api/chat from fileIds (inlined when small, retrieved otherwise) and knowledge bases chosen in the composer or attached to an agent, framed as untrusted data; the allowed formats and size limits live in src/lib/file-types.ts — one list for browser and server.
- Official Registry items are original TechNova designs kept as files in drizzle/registry/ (manifest.json) and installed by a generated, re-runnable migration (node scripts/build-registry-migration.mjs <new migration name>, latest 0037); HTML items preview in sandboxed iframes without same-origin — one reviewable source for content and safe live previews.
- Official Registry designs are included with Creator and Pro: RLS, registry_download and registry_remix go through registry_item_open (migration 0036), Starter/Essential keep one open design (Halo, …0101) and see the rest as locked cards from registry_catalog (metadata only) — content never reaches accounts without access.
- Arena is hidden for now (no links; /classement and /dashboard/arena redirect, code kept). The public Arena ranking (/classement) is loaded by a server function that returns only the aggregated arena_leaderboard rows (blind votes), never battles or voters — public trust content without exposing user data.
- The admin console (/dashboard/admin, sidebar link for admins only) reads revenue, users and credit totals through service_role-only SQL aggregates (migration 0033) called from server functions that re-check has_role; suspensions combine an auth ban with account_suspensions, which /api/chat and API-key auth also check — admin power stays server-side and the ledger is never loaded whole.
- Plan limits from the /tarifs table (except the development/terminal section) live in src/lib/plans.ts; the tier is the highest credited pack (account_tier, migration 0034, service_role only) and every gated action re-checks it on the server (plan.server.ts) or in a trigger (share links, agents), answering PLAN_UPGRADE_REQUIRED:<feature> that the UI turns into an upgrade message — the browser never decides access.
- "Credits used" (dashboard overview, admin users) is read from the credit ledger like the balance (charge + usage + reserve + refund, migration 0035); media generations also write usage_logs so the Usage page lists them — used and remaining always add up.
- Cookie consent (src/lib/consent.ts + CookieConsent in __root, hidden on /s/ user sites): accept / reject / customize with equal weight, choice kept 6 months; strictly necessary storage and explicitly chosen language/theme (EXPLICIT_CHOICE_KEYS) need no consent, other preference keys go through savePref and are wiped on refusal; no analytics or ads exist — the /cookies policy (FR, authoritative) lists every key and must be updated when storage changes.
- Generated media show bare in the chat (no frame, no prompt) with Download and, for images, Edit: Edit puts the image in the composer and the next message runs imageEditModel (google/nano-banana-edit, not in the pickers) with the archived file as source (sourceId, owner-checked, 14-day retention); link previews on every page use the hero poster (absolute og:image).
- Dashboard themes (src/lib/dashboard-themes.ts, menu under "Thèmes" in the profile menu, stored in technova-dashboard-theme): Brume, Soie, Crépuscule, Abysse, Améthyste (dark) and Pastel, Azur, Givre, Perle (light, Azur by default; Perle is the pearl-grey gradient of the FAQ reference image); Azur/Crépuscule follow the ivory-haze mockup, Abysse/Améthyste the two dark reference images (look-specific orb, composer edge and sidebar); retired Apple/Papier/Sable/Ciel/Ivoire open Azur, Réverbère/Graphite/Obsidienne open Brume; on desktop the sidebar floats as a rounded glass card inside a padded shell, and menus/dialogs over the dashboard are frosted but near-opaque; Soie also restyles the sidebar glass; the mode drives the sidebar, the look only restyles .dashboard-content (wallpaper gradients, glows, glass variables, composer edge) — only Soie changes the sidebar (its glass and a moving light), by explicit request.
- Dashboard content panels (bordered bg-card surfaces in main, plus the "Sites à visiter" marquee, which sits at the bottom of non-thread pages; today's date shows at the top left of the content; the chat home has no "recent conversations" block, history lives in the sidebar) turn into the ivory-haze mockup's flat frosted glass from CSS alone in styles.css (55% fill in the look's tint, blur 40px saturate 150%, soft ambient shadow, no border/rim/sheen; nested cards and tints use a 70% "chip" glass; the desktop sidebar uses the same panel glass), except chat threads, the composer and portaled dialogs; dashboard sidebar is frosted glass (sidebar-glass) with a faint West-African-textile pattern on every look (barely visible in dark mode), and below the lg breakpoint it is a fuller, strongly blurred glass so nothing behind it stays readable; dashboard grid cells get min-width 0 so long titles truncate instead of widening panels past a phone screen; the plan badge and the spinning avatar ring take the colours of the highest pack bought (plan-<key> classes, usePlan); a confirmed payment opens PaymentSuccess (confetti, drawn tick, credits added) before reloading.
- Confirmations use confirmDialog / promptDialog (src/components/ConfirmHost.tsx, host mounted in __root): one accessible modal with title, explanation and Cancel / action buttons (red for destructive actions) — never window.confirm, alert or prompt.
- Payments are orchestrated server-side (payment-routing.ts + payments.functions.ts): cards and Mobile Money of FeexPay-covered countries/operators go to FeexPay (feexpay.server.ts, webhook /api/public/feexpay-webhook with a Bearer secret), everything else and any FeexPay failure to Nyole; payments.server.ts re-reads the provider status and credits once — config in docs/paiements-feexpay.md, secrets only in Vercel.
- Account deletion (Settings → Supprimer mon compte, account_deletions, migration 0038) keeps everything 30 days, cancellable from a dashboard banner after signing in again; the daily /api/public/media-purge then removes stored files and the auth user (cascade), while payment records (no foreign key) stay for accounting — the privacy policy states this delay.
- SEO: public routes build their head with pageHead (src/lib/seo.ts: canonical on www.technovaihub.com, og/twitter tags, robots, JSON-LD Organization/WebSite/WebApplication/FAQPage/Breadcrumb from real content); private routes are noindex; public/robots.txt, public/sitemap.xml (update when a public page is added) and public/llms.txt describe the site to crawlers — one place for search metadata.
- Chat thread: a disclaimer sits above the chat box, prompts you sent offer resend / copy / share / edit (edit puts the text back in the box), generated images open full screen (portal viewer, Esc to close), the thinking state and media in progress show the turning ThinkingSpinner with « Réflexion en cours » above an even blue dot field with real progress (or elapsed time), the dashboard content shows a thin visible scrollbar (sidebar stays clean), and media requests are detected from infinitives and polite forms (« peux-tu générer une image… ») while the chat prompt says TechNova creates media itself.
- Abuse guards: every billable action reserves credits first through reserveCredits (credits.server.ts), which also refuses suspended accounts (assertNotSuspended, media too); a chat reply stopped by the visitor is still billed at least the mode price; the public API reserves the worst case before calling the provider and bills usage.cost; the welcome bonus needs a confirmed e-mail (migration 0040).
